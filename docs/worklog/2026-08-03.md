# 2026-08-03 작업 로그

`oh-my-peekly` 프로젝트 킥오프부터 v0.1.17까지, 하루 만에 진행된 전체 작업 기록.

## 기획 및 팀 구성

- `~/Downloads/Peekly_서비스_설계.md` 설계 문서를 기반으로 개발 전담 서브에이전트 5개 구성 (`.claude/agents/`): `peekly-mcp-core`, `peekly-report-builder`, `peekly-platform-dev`, `peekly-workflow-writer`, `peekly-flow-reviewer`.
- 개발 컨벤션(`docs/CONVENTIONS.md`) 작성, Conventional Commits + `commit-and-tag-version`으로 버전업 방식 확정, 저장소를 `https://github.com/minsu0707/oh-my-peekly.git`로 지정.

## MCP 서버 및 도구 구현

- **v0.1.0**: `browser_navigate`/`browser_click`/`browser_type`/`browser_screenshot` — Playwright 기반 브라우저 자동화 도구.
- **v0.1.1**: `sitemap_crawl`(같은 도메인 BFS 크롤링), `estimate_cost`(예상 소요 시간/비용 산출) 추가.
- **v0.1.2**: `generate_report` — python-pptx 서브프로세스로 템플릿 슬라이드를 복제하고 필드를 치환하는 PPT 보고서 생성 도구.
- **v0.1.3**: `save_credentials`/`get_credentials`(keytar), `find_local_file`, `open_in_viewer` — 자격증명 캐싱 및 로컬 파일 탐색/뷰어 오픈.
- **v0.1.4**: `.claude/skills/peekly/SKILL.md` 작성 — 위 도구들을 사전확인→크롤링→테스트→검수→보고서 생성 흐름으로 연결.
- **v0.1.5**: `peekly install-skill` CLI 서브커맨드 추가 (SKILL.md를 프로젝트에 설치).

## 설치 흐름 안정화

- **v0.1.6~0.1.7**: 실제 설치→사용 경로를 처음부터 끝까지 검증하며 버그 2개 발견/수정 — `src/index.ts` shebang 누락, `npm install -g .`가 의존성을 설치하지 않는 문제. `git clone → npm install → npm install -g .` 3단계가 유일하게 검증된 설치 순서임을 확정하고, git 설치 시 네이티브 모듈(keytar) 빌드가 깨지는 문제 때문에 `dist/`를 git에 커밋하는 방식으로 우회.
- **v0.1.8**: 초보자도 따라 할 수 있게 설치 가이드를 더 풀어서 작성.
- **v0.1.9**: 설치를 "한 번만 복붙"으로 끝낼 수 있도록 `claude mcp add -s user`, `install-skill` 기본 경로를 개인 스코프(`~/.claude/skills`)로 변경.
- **v0.1.10**: Windows 원라이너를 PowerShell 5.1의 `&&` 미지원 문제 때문에 cmd.exe 기준으로 변경.
- 문서 정리: `CONVENTIONS.md`, `CHANGELOG.md`를 `docs/`로 이동 (README.md는 GitHub 렌더링 때문에 루트 유지).

## 실사용 피드백 반영

- **v0.1.11**: 채팅 인터페이스에서는 "Enter로 기본값" 방식이 동작하지 않는 문제 → `AskUserQuestion`으로 전면 교체, 파일명 단계는 Y/N 먼저 묻고 "직접 입력" 선택 시에만 자유 텍스트를 받는 2단계 방식으로 변경.
- **v0.1.12**: 이슈별 Y/N 검수가 귀찮다는 피드백 → 자동 포함으로 변경했다가, 이를 다시 사용자가 설정 가능하게 해달라는 요청에 따라 `get_setting`/`save_setting` MCP 도구 + `~/.peekly/config.json` 영속 설정 시스템을 구축 (`issueReviewMode`).
- **v0.1.13**: PPT 파일이 "복구가 시도될 수 있습니다" 경고와 함께 열리는 문제 — `_remove_slide_at`이 슬라이드를 제거할 때 presentation part의 관계(rel)를 같이 지우지 않아 zip 내부에 동일 이름 파트가 중복 생성되던 것이 원인. 관계까지 제거하도록 수정하고 zip 직접 검사로 재검증.
- **v0.1.14**: 실제 생성된 보고서 스크린샷 피드백 — 긴 텍스트가 박스를 늘려 스크린샷을 가리는 문제를 `MSO_AUTO_SIZE.TEXT_TO_FIT_SHAPE`(텍스트 축소)로 해결, 문제 위치를 스크린샷 위에 표시하는 `problemArea`(테두리만 있는 도형) 기능과 `browser_bounding_box` 도구 추가.
- **v0.1.15**: 화면 하나씩 순차 테스트하느라 너무 느리다는 피드백 → 브라우저 세션을 여러 개(`browser_new_session`/`browser_close_session`, `sessionId` 파라미터)로 늘려 메뉴별로 병렬 테스트하도록 구현. 하나의 브라우저 컨텍스트를 공유해 로그인 쿠키가 모든 탭에 자동으로 이어짐. `parallelSessionCount` 설정 추가.
- **v0.1.16**: 문제 위치 표시 테두리가 대상 요소에 너무 딱 붙어 있다는 피드백 → `PROBLEM_AREA_PADDING`으로 여유 공간을 주고, 스크린샷 경계를 넘지 않게 clamp 처리.
- **v0.1.17**: 첨부된 PPT 템플릿에서 직접 작업하지 말고 항상 새 파일을 만들어 그 위에서 작업하라는 요청 → 템플릿 복사 후 편집하는 기존 동작은 유지하면서, `outputPath`가 실수로 `templatePath`와 같아지는 경우를 명시적으로 거부하는 가드를 Node/Python 양쪽에 추가. README.md/CONVENTIONS.md 제목을 실제 저장소명인 `oh-my-peekly`로 변경.

## 남은 과제 (README "알려진 제약" 참고)

- macOS 분기(`mdfind`, `open`) 실제 기기 검증 미완료 (개발 환경이 Windows).
- 실제 PPT 템플릿 파일 기준 검증 미완료 — `{{breadcrumb}}` 토큰, `"screenshot"` 이름 shape 등 플레이스홀더 규칙은 잠정안.
- npm 레지스트리 배포 안 함 (GitHub 클론 설치만 지원).
- Codex(AGENTS.md) 지원 미착수 — 설계 문서상 Claude Code 경로 검증 이후로 보류 중.
