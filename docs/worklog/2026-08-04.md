# 2026-08-04 작업 로그

병렬 세션 수 설정을 사용자 요청에 따라 캐싱하지 않는 방식으로 되돌린 하루.

## 설정 동작 변경

- **v0.1.19**: `parallelSessionCount`(몇 개 브라우저 탭으로 화면을 나눠 동시 테스트할지)를 `issueReviewMode`와 똑같이 한 번 물어보고 계속 캐시하던 방식에서, **매 실행마다 다시 묻는** 방식으로 변경. 사용자가 실행할 때마다 대상 서비스 부하 상황 등에 따라 다르게 고르고 싶다는 요청 때문. 다만 완전히 캐시를 없애지는 않고, `save_setting`으로 직전 선택값은 계속 저장해서 다음 질문의 `(권장)` 라벨이 직전 선택을 반영하도록 함 — 저장은 하되 절대 질문 자체를 건너뛰지는 않는 절충.
- `skills/peekly/SKILL.md`와 `.claude/skills/peekly/SKILL.md`(project-scope dogfooding 사본) 동기화. 플러그인은 버전을 안 박아둔 덕분에 `claude plugin update oh-my-peekly@oh-my-peekly` 한 번으로 최신 커밋을 그대로 받아오는 것 실제로 확인함 (전날 v0.1.18에서 의도한 대로 동작).

## 설치 제거 + 문서 점검

- 사용자 요청으로 이 개발 머신에서 Peekly를 전부 제거: `npm uninstall -g peekly-mcp`, `claude plugin uninstall oh-my-peekly@oh-my-peekly`, `claude plugin marketplace remove oh-my-peekly`. 프로젝트 폴더 자체의 `.mcp.json`은 삭제 대상이 아님(플러그인 동작에 필요한 파일) — 이 폴더 안에서 작업하면 "peekly pending approval"로만 표시되는 게 정상이라고 확인.
- README.md 점검 요청에 사용법("사용법") 섹션이 v0.1.11 이전(Enter로 기본값 받던 방식) 설명 그대로 남아있던 걸 발견해서 수정 — 지금은 전부 선택지 기반이고, 이슈 검수는 기본값(자동 포함)에서는 아예 안 물어본다는 점, 1단계에서 이슈 검수 방식/병렬 세션 수도 물어본다는 점을 반영. 설치/제거 섹션 자체는 이미 플러그인 방식으로 정확했음.

## 프로젝트 스코프 스킬 vs 플러그인 스킬 중복 확인

- 플러그인을 언인스톨한 직후에도 이 저장소 폴더 안에서는 `/peekly`(project-scope `.claude/skills/peekly/` 사본)와 `/oh-my-peekly:peekly`(플러그인, 재시작 전이라 세션에 남아있던 것)가 동시에 뜨는 걸 사용자가 실제 화면으로 확인해줌 — 어제 CONVENTIONS.md에 "미확인"으로 남겨뒀던 중복 가능성이 사실로 확인됨. 에러는 아니고 커맨드가 두 개로 보이는 정도라 `.claude/skills/peekly/`는 그대로 두기로 함 (`docs/CONVENTIONS.md` 8-1절에 기록).
